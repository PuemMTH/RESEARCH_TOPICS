FigCaps-HF: A Figure-to-Caption Generative Framework and Benchmark with Human Feedback

เสนอ framework ที่ใช้ RLHF (แบบ offline, Upside-Down RL) เพื่อ fine-tune โมเดล figure-captioning ให้ caption ตรงกับความชอบของผู้อ่าน (reader preference) พร้อม benchmark dataset 106,834 figure-caption pairs ที่มี feedback score กำกับ

Ashish Singh, Ryan A. Rossi, et al. (UMass Amherst / Adobe Research) arXiv preprint 2023 arXiv:2307.10867

ปัญหาที่ Paper นี้แก้

  • โมเดล figure-captioning ส่วนใหญ่ train จาก figure-caption pairs ที่ดึงมาจาก paper จริง (เช่น SciCap) แต่ caption เหล่านี้จำนวนมาก "generic" และไม่ informative — งานก่อนหน้าพบว่า caption กว่า 50% ใน arXiv cs.CL ถูกผู้เชี่ยวชาญตัดสินว่า "ไม่ช่วยอะไร" (unhelpful)
  • การ train บนข้อมูลคุณภาพต่ำแบบนี้ทำให้โมเดล generalize ได้ไม่ดีและไม่สอดคล้องกับสิ่งที่ผู้อ่านต้องการจริง ๆ
  • คำถามหลัก 2 ข้อที่ paper ตอบ: (1) จะใส่ expert feedback เข้าไปใน training โดยไม่เพิ่ม compute overhead ได้อย่างไร (2) จะ scale การสร้าง feedback ได้อย่างไรโดยใช้แรงงาน annotation มนุษย์น้อยที่สุด

Key Contributions

  • RLHF framework แบบ offline: ใช้ Upside-Down RL (reward-conditioned behavioral cloning) แทน on-policy RL (เช่น PPO) — เทรน reward model ครั้งเดียวแล้วไม่ต้องใช้ระหว่าง train captioning model ทำให้ประหยัด compute
  • Human-Feedback Prediction Model: label ข้อมูลจริงแค่ 438 ตัวอย่างด้วยผู้เชี่ยวชาญ (4 มิติ: Helpfulness, Takeaway, Visual-descriptiveness, OCR) แล้วเทรนโมเดล regression ไป predict score ให้กับ dataset ทั้งหมด 106,834 pairs
  • Benchmark dataset สาธารณะ: ปล่อย dataset ที่มี feedback score กำกับทุก figure-caption pair เพื่อให้ชุมชนวิจัยใช้ต่อ
How It Works

Methodology

1

Pipeline ภาพรวม

3 ขั้นตอนหลัก

(1) Standard figure-captioning pipeline — vision encoder + language encoder-decoder train ด้วย LM loss ปกติ → (2) เทรน Human-Feedback Prediction Model จาก labeled subset เล็ก ๆ เพื่อ infer feedback score ให้ data ทั้งหมด → (3) ใช้ score เหล่านั้นเป็น reward เพื่อ fine-tune captioning model ด้วย offline RLHF (UDRL)

2

Human Feedback Prediction Model

เทรนบน control set $D_h$ (438 pairs ที่ rate โดยผู้เชี่ยวชาญแบบ 5-point Likert scale บน 4 มิติ: Helpfulness, Takeaway, Visual, OCR) ใช้ MCSE เป็น embedding function (frozen) ต่อด้วย 2-layer MLP เป็น regression head เทรนด้วย MSE loss แล้วนำไป predict score แบบ continuous ให้ caption ทุกตัวใน dataset ใหญ่ $D_w$ (106,834 pairs)

3

Offline RLHF ด้วย Upside-Down RL

มองปัญหาเป็น RL: figure = state, caption = action, predicted feedback score = reward เลือกใช้ offline UDRL (reward-conditioned behavioral cloning) แทน on-policy RL เพราะง่ายกว่าและไม่ต้องเทรน reward model ระหว่าง policy optimization จากนั้น binarize reward score เป็น control token <|good|> / <|bad|> ด้วย threshold แล้ว prepend/append เข้ากับ caption ตอน fine-tune captioning model ด้วย LM loss ที่ condition บน control token นี้

Key Numbers
  • BLIP + RLHF: BLEU +35.7%, ROUGE-L +16.9%, METEOR +9%, CIDEr +11.4% เทียบกับ fine-tune ปกติ
  • ViT+GPT2 + RLHF: BLEU +11.1%, CIDEr +5.1%
  • BLIP ได้ผลดีกว่า ViT+GPT2 เพราะ image encoder กับ text decoder ถูก pre-train ร่วมกันมาแต่แรก (jointly aligned) ขณะที่ ViT+GPT2 เพิ่งมาเรียนรู้ alignment ตอน fine-tune
  • Human-feedback prediction model มี out-of-sample MSE ต่ำ (0.076–0.095) แสดงว่า generalize ดีไปยัง caption ที่ไม่เคยเห็น
Gaps & Future Work

Limitations (จาก paper)
  • UDRL fine-tuning ต้อง update ทุก parameter ของโมเดล ไม่ใช่ parameter-efficient (เช่น LoRA) จึงใช้ compute เยอะกว่าที่ควร
  • Feedback ที่ใช้ปรับ alignment เป็น feedback ของ "ผู้อ่านทั่วไป" เท่านั้น ยังไม่ครอบคลุม use case เฉพาะกลุ่ม เช่น assistive tool สำหรับผู้พิการทางสายตา
  • Reward score ต้อง binarize เป็น good/bad ก่อนใช้ ทำให้สูญเสีย granularity ของ feedback ที่เป็น continuous
  • Context ที่ใช้ generate caption คือ "รูป" อย่างเดียว (figure-only หรือ figure+OCR) — ไม่ได้ดึง context จากเนื้อหารอบข้างของเอกสาร เช่น mention paragraph, section, abstract

What I Borrow

แนวคิดเรื่อง evaluation ที่แยกมิติชัดเจน (Helpfulness, Takeaway, Visual-descriptiveness, OCR/text-alignment) ตรงกับ objective ข้อ 4 ของ thesis ที่ต้องการประเมิน caption ทั้งด้านความถูกต้อง ความสอดคล้องกับบริบท และความสามารถถ่ายทอดสาระสำคัญ — สามารถยืมกรอบ 4 มิตินี้มาออกแบบ evaluation rubric ของ thesis ได้โดยตรง แทนที่จะวัดแค่ BLEU/ROUGE

Where I Diverge

FigCaps-HF เน้นแก้ปัญหาที่ "training signal" (reader-preference alignment ผ่าน RLHF) ไม่ได้แตะเรื่อง context จากเอกสารเลย — ใช้แค่ภาพ (+OCR) เป็น input ส่วน thesis ของเราเน้นที่ "input context" คือดึง context จากเนื้อหาเอกสาร (paragraph, section, การอ้างอิงรูป) มาเสริมการสร้าง caption ดังนั้นทั้งสองงานแก้คนละจุดของปัญหาเดียวกัน และอาจ complement กันได้ — ใช้ context-aware generation ของเราเป็น base model แล้วเสริมด้วย RLHF-style alignment ของ FigCaps-HF ทีหลังเพื่อ refine คุณภาพเพิ่มอีกชั้น

Open Questions

ถ้าใช้ context-aware caption เป็น input ของ human-feedback prediction model แบบ FigCaps-HF จะช่วยให้ reward signal แม่นขึ้นไหม? และ scoring scheme 4 มิติแบบนี้ scale ไปใช้กับ caption ที่มี context ยาวขึ้น (เช่น ดึงมาจากทั้ง section) ได้โดยไม่ต้อง re-annotate ใหม่หรือไม่?

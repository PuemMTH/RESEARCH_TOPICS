Natural Language Interface for Queries on Databases with Sensitive Information

Framework ที่รวม OCR, Neo4j graph database, และ LLM Cypher translation เพื่อให้ผู้ใช้ที่ไม่มีความรู้ด้าน query language สามารถ query ข้อมูล sensitive ได้อย่างปลอดภัยผ่านภาษาธรรมชาติ

Abstract & Contributions

ภาพรวม

!

ปัญหาที่ Paper นี้แก้

  • ผู้ใช้จาก social sciences, law enforcement, healthcare ต้องการ query ข้อมูล sensitive (criminal justice, medical records, education data) แต่ไม่มีทักษะ SQL/Cypher
  • ข้อมูลที่ต้องการมักอยู่ในเอกสารที่ scan แล้ว (unstructured) ต้องผ่าน OCR ก่อน
  • Conventional SQL interfaces ไม่รองรับ graph relationships ที่ซับซ้อนของข้อมูล sensitive เหล่านี้
★

Key Contributions

  • OCR-to-Graph Pipeline: ใช้ OCR extract structured data จาก scanned documents แล้ว store ใน Neo4j graph database ที่ model entity relationships ได้ดีกว่า relational DB
  • LLM-powered Natural Language to Cypher: แปลง natural language query เป็น Cypher query อัตโนมัติ โดยไม่ต้องมีความรู้ด้าน query language
  • Privacy-preserving design: architecture ออกแบบเพื่อจัดการ sensitive data — ไม่ expose schema หรือ sample data ไปยัง external LLM services

System Architecture

Pipeline

เอกสาร → OCR extraction → structured entities → Neo4j graph DB → NL query input → LLM translation → Cypher → graph query → results

  • OCR Layer: extract entities และ relationships จาก unstructured/scanned documents
  • Neo4j Graph DB: store entities และ relationships ใน graph structure ที่เหมาะสำหรับ complex relational queries
  • LLM Query Translator: รับ natural language input แปลงเป็น Cypher query โดยใช้ graph schema เป็น context

Privacy Considerations

Security

ข้อมูล sensitive ต้องไม่ถูก expose ไปยัง external LLM APIs — design ต้องการ local deployment หรือ schema abstraction layer ที่ปกป้อง sensitive field names และ sample data

Results & Benchmarks

Application Domains
  • Criminal justice databases (law enforcement)
  • Healthcare records (medical professionals)
  • Education data (researchers, administrators)
Key Insight
  • Graph database (Neo4j) เหมาะกว่า relational DB สำหรับ entity-relationship-heavy sensitive data
  • Natural language → Cypher translation ช่วยให้ non-technical users query complex graph data ได้
  • OCR integration ทำให้ระบบใช้งานได้กับเอกสารที่ยังไม่ได้ digitize
Gaps & Future Work

ข้อจำกัดและทิศทางต่อไป

Limitations
  • LLM Cypher translation accuracy ขึ้นอยู่กับ quality ของ graph schema — complex schemas อาจทำให้ translation ผิดพลาด
  • OCR accuracy สำหรับ handwritten หรือ low-quality scans ยังเป็น bottleneck
  • Privacy-preserving approach ยังไม่ได้รับการ formal verification — เป็น design intent มากกว่า proven guarantee
  • Paper ไม่ได้รายงาน quantitative evaluation metrics (accuracy, F1) ที่ชัดเจน

What I Borrow

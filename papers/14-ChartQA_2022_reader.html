ChartQA: A Benchmark for Question Answering about Charts with Visual and Logical Reasoning

benchmark ขนาดใหญ่สำหรับ Chart Question Answering ที่ใช้คำถามจากมนุษย์จริงๆ รวมถึง visual reasoning และ arithmetic reasoning บน real-world charts — เป็นเกณฑ์มาตรฐานหลักสำหรับวัด chart understanding และ gap ระหว่าง human กับ machine performance

Masry, Long, Tan, Joty, Hoque ACL Findings 2022 arXiv:2203.10244
Abstract & Contributions

ภาพรวม

ปัญหาที่ Paper นี้แก้

  • Dataset ก่อนหน้า (FigureQA, DVQA, PlotQA) ใช้ template-based questions ที่ไม่เป็นธรรมชาติ และ charts ที่ generate จาก Matplotlib ไม่ reflect real-world styles
  • Fixed-vocabulary answers ทำให้ไม่รองรับ complex arithmetic questions เช่น "how many more" หรือ "what is the ratio"
  • ขาด visual reasoning questions ที่อ้างถึง visual attributes เช่น สี, รูปร่าง, trend ของกราฟ

Key Contributions

  • ChartQA Benchmark: 9,608 human-written + 23,111 machine-generated questions บน 20,882 real-world charts จาก 4 แหล่ง (Statista, Pew, OECD, OWID)
  • VisionTaPas: Visual features (ResNet-50) + TaPas table QA — unified approach สำหรับ chart QA
  • VL-T5: Multimodal T5 ที่รับ image features (Faster R-CNN) + linearized data table + question → generate answer แบบ generative
  • ChartOCR Extension: ขยาย ChartOCR ให้ extract fully-structured data table รวม axis labels, legends
How It Works

Methodology

Data Collection

Charts รวบรวมจาก 4 แหล่ง: Statista (business infographics), Pew Research (survey data), OECD (economic data), Our World in Data (global statistics) — ครอบคลุม topics หลากหลาย. Human annotators เขียน 2 คำถามต่อ chart โดยเน้น visual reasoning (อ้างถึง color/shape) และ logical reasoning (arithmetic operations).

ChartQA-M: Machine-Generated Questions

ใช้ T5 fine-tuned สำหรับ question generation จาก human-written chart summaries เพื่อขยาย dataset ด้วย cost ต่ำกว่า human annotation โดยยังคงความหลากหลายทางภาษา

Model Pipeline

  • Step 1 — ChartOCR: Extract structured data table จาก chart image (bar heights → values, axis labels, legend)
  • Step 2 — TaPas/T5: รับ question + data table → table QA
  • Step 3 — VisionTaPas/VL-T5: เพิ่ม visual features จาก ResNet-50/Faster R-CNN เข้า unified model

Gaps & Future Work

ข้อจำกัดและทิศทางต่อไป

  • OCR error propagation — ถ้า ChartOCR extract data table ผิด ทุก downstream model พังตาม ไม่มี error correction
  • ไม่ครอบคลุม scientific figures ที่มี complex multi-panel layouts, domain-specific notation ใน academic papers
  • ไม่มี surrounding paper context — charts ใน ChartQA มาจาก news sites ไม่ใช่ academic papers
  • Fixed evaluation metric (relaxed accuracy ±5%) อาจไม่เหมาะกับ open-ended evaluation
Connection to My Research

ความเกี่ยวข้องกับวิทยานิพนธ์

What I Borrow

ChartQA benchmark ใช้เป็น evaluation dataset ที่ complement SciCap — ถ้า model สร้าง caption ดีต้องสามารถตอบ QA จาก caption นั้นได้ด้วย (QA-based caption evaluation). ChartOCR pipeline เป็น component สำคัญใน RAG-based captioning system

Where I Diverge

ChartQA focus ที่ QA (given Q, find A) แต่งานเราคือ captioning (given figure, write description). Scientific charts ใน academic papers มี surrounding context ที่สำคัญซึ่ง ChartQA ไม่มี

Research Gap

ไม่มีงานที่เชื่อม ChartQA understanding กับ SciCap captioning — QA-capability สามารถใช้เป็น auxiliary training signal หรือ evaluation proxy สำหรับ caption quality ได้

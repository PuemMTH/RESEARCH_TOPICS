ChartQA: A Benchmark for Question Answering about Charts with Visual and Logical Reasoning

benchmark ขนาดใหญ่สำหรับ Chart Question Answering ที่ใช้คำถามจากมนุษย์จริงๆ รวมถึง visual reasoning และ arithmetic reasoning บน real-world charts — เป็นเกณฑ์มาตรฐานหลักสำหรับวัด chart understanding

Masry, Long, Tan, Joty, Hoque ACL Findings 2022 arXiv:2203.10244

ปัญหาที่ Paper นี้แก้

  • Template-based questions ไม่เป็นธรรมชาติ: Dataset ก่อนหน้าเช่น FigureQA, DVQA ใช้ questions ที่ generate จาก template ทำให้ขาด diversity และ naturalness ที่เห็นในการถามคำถามจริง
  • Synthetic charts ไม่ reflect real-world: Charts ส่วนใหญ่ถูก plot ด้วย Matplotlib ทำให้ style ไม่หลากหลายเหมือนกราฟในชีวิตจริง
  • Fixed-vocabulary answers: คำตอบมาจาก vocabulary ขนาดเล็ก (yes/no, axis labels) ทำให้ไม่รองรับ complex arithmetic questions เช่น "how many more…" หรือ "what is the ratio of…"
  • ขาด visual reasoning questions: ไม่มี dataset ที่รวม questions เกี่ยวกับ visual attributes เช่น สี, รูปร่าง, trend ของกราฟ

Key Contributions

  • ChartQA Benchmark: Large-scale benchmark ด้วย 9,608 human-written questions + 23,111 machine-generated questions จาก human-written chart summaries บน 20,882 real-world charts จาก 4 แหล่ง (Statista, Pew, OECD, OWID)
  • สองโมเดลใหม่: VisionTaPas (visual features + TaPas) และ VL-T5 (visual language T5) ที่รวม visual features และ extracted data table ใน unified framework
  • ChartOCR Pipeline: ขยาย ChartOCR เพื่อ extract structured data table จาก chart image สำหรับส่งเข้า QA model
  • State-of-the-art results: VisionTaPas ทำได้ดีที่สุดบน PlotQA V1/V2 และบน ChartQA เอง แม้ยังมี gap กับ human performance อยู่มาก

How It Works

Methodology

1

Data Collection Pipeline

Chart Sources

Charts รวบรวมจาก 4 แหล่ง: Statista (infographics เชิงธุรกิจ), Pew Research (survey data), OECD (economic data), Our World in Data (global statistics) — ครอบคลุม topic หลากหลาย ตั้งแต่ สังคมศาสตร์ถึงเศรษฐศาสตร์

  • Human-written questions (ChartQA-H): Annotators ถูกขอให้เขียน questions ที่ต้องการ visual reasoning (อ้างถึง color/shape) และ logical reasoning (arithmetic operations) — 2 questions ต่อ chart
  • Machine-generated questions (ChartQA-M): ใช้ T5 fine-tuned สำหรับ question generation จาก human-written chart summaries — ได้ questions ที่หลากหลายแต่ควบคุม quality ไม่ได้ 100%
  • Chart summary annotation: ก่อน generate ChartQA-M ต้องมี human-written summaries อยู่แล้ว ซึ่ง summaries เหล่านี้เองก็เป็น training data ที่มีประโยชน์สำหรับ captioning
2

Model Architecture: VisionTaPas & VL-T5

Full Pipeline

Chart Image → ChartOCR (data extraction) → Structured Data Table → [TaPas/T5 + Visual Features] → Answer

  • ChartOCR Extension: ดัดแปลง ChartOCR ให้ extract ไม่เพียงแค่ raw values แต่รวม axis labels และ legends ด้วย เพื่อสร้าง fully-structured data table
  • VisionTaPas: ต่อ visual tokens จาก ResNet-50 เข้ากับ TaPas (BERT-based table QA) — ทำให้ model เห็นทั้ง visual context และ structured data
  • VL-T5: ใช้ VL-T5 (multimodal T5) ที่รับ image features จาก Faster R-CNN และ text input เป็น "question + linearized table" — generate answer แบบ generative
  • TaPas (baseline): TaPas ล้วนๆ โดยไม่มี visual features — ใช้เป็น ablation เพื่อวัดผลของ visual features

Key Insights จาก Results
  • Human accuracy 80.5% vs. best model 56.5% → gap ใหญ่มาก (~24%) แสดงว่า task ยังเป็น open problem
  • Visual features ช่วยเล็กน้อย (+0.6% สำหรับ VisionTaPas vs TaPas) แต่ไม่ใช่ silver bullet
  • ChartQA-H (human questions) ยากกว่า ChartQA-M (machine questions) อย่างเห็นได้ชัด
  • T5-based generative approach แพ้ TaPas-based table QA ใน chart domain
Gaps & Future Work

ข้อจำกัดและทิศทางต่อไป

Limitations
  • OCR error propagation: ถ้า ChartOCR extract data table ผิด ทุก downstream model ก็พังตาม — ไม่มี error correction mechanism
  • Limited chart types: เน้นที่ bar, line, pie charts — ไม่ครอบคลุม scatter plots, heatmaps, complex multi-panel figures ที่พบใน scientific papers
  • ไม่มี scientific context: Charts ใน ChartQA มาจาก news/stats websites ไม่ใช่ academic papers — ไม่มี surrounding text, captions หรือ paper context
  • Fixed evaluation metric: ใช้ relaxed accuracy (±5% tolerance) ซึ่งอาจไม่เหมาะกับ open-ended evaluation
  • Single-turn QA เท่านั้น: ไม่รองรับ multi-turn dialogue หรือ iterative chart exploration
Connection to My Research

ความเกี่ยวข้องกับวิทยานิพนธ์

What I Borrow

ChartQA benchmark ใช้เป็น evaluation dataset ที่ complement กับ SciCap — ถ้า model สร้าง caption ดีต้องสามารถตอบ QA จาก caption นั้นได้ด้วย (QA-based evaluation). นอกจากนี้ ChartOCR pipeline สำหรับ extract structured data table เป็น component สำคัญใน RAG-based captioning system ของเรา

Where I Diverge

ChartQA focus ที่ question answering (given a Q, find A) แต่งานวิจัยของเราคือ caption generation (given a figure, write a comprehensive description). การ generate caption ที่ดีต้องการ understanding เหมือน QA แต่ output format และ evaluation ต่างกันโดยสิ้นเชิง. นอกจากนี้เรา focus ที่ scientific charts ใน academic papers ซึ่งมี surrounding context ที่สำคัญ

Open Questions / Research Gap

GAP ที่ชัดเจน: ไม่มีงานที่เชื่อม ChartQA (understanding) กับ SciCap (captioning) เข้าด้วยกัน — งานวิจัยของเราสามารถใช้ QA-capability เป็น auxiliary training signal หรือ evaluation proxy สำหรับ caption quality ได้. อีก gap คือ ChartQA ไม่มี scientific paper context ซึ่งงานเราจะ address ด้วย RAG
